## 已明确

- 名称：a-watcher / Agent Watcher。
- 首期平台为 macOS；极低系统资源占用优先于跨平台。
- 首期包含状态、用量、账户额度三类能力，并支持 Codex 和 Claude Code。
- 用户确认两者均为官方订阅账户。
- 界面要美观、简洁、符号化；不做需要长期开着的复杂控制台。
- 用户已选定一期菜单栏形态，刘海条与悬浮条暂不纳入一期。
- 用户认可整体方案；Swift + AppKit 作为后续技术验证方向。
- 面板按约 300 pt 精简：保留项目与关键数字，说明移入悬停和详情，多用可辨识符号。
- 用户确认额度进一步简化，主面板与额度详情均不使用进度条。
- 本轮不安装额外设计技能，用户已明确选择直接完成准备工作。

## 本轮验证结果

- 用户已授权完成调研验证，全部 OK 后开发；本轮已实际运行两个原生 UI 样机、两种额度请求与大日志/bridge 探针。
- [验证报告](tech/spikes/2026-11-06-validation.md)：Codex 原生额度 HTTP 200；两种 UI 静态样机的物理占用均约 19 MiB；10 分钟空闲 CPU 均通过目标。
- Swift 大文件探针经释放边界修正后峰值约 12.81 MiB，但 56 条超大单行被跳过，统计覆盖仍不完整；合成 bridge 60 事件送达，不冒充真实宿主全状态验证。
- Claude 当前环境 OAuth token 查询额度 HTTP 403；用户已明确暂缓，不再尝试其凭据。它不再阻挡 Codex 首接入。
- 已创建正式产品工程、诊断 CLI 与自包含检查器；实验代码仍独立保留，不作为正式实现直接合入。

## 下一步顺序

1. 用户实际使用首个 Codex 版本，补齐真实点击与键盘交互验收。
2. 补全压缩归档与大行元数据读取，减少部分统计；用固定口径交叉核对完整用量。
3. 在保留既有配置的前提下，交付可选精确事件接入，覆盖等待批准/输入与克制通知；Codex 信任由其自身流程完成。
4. 完成费用估算、设置和长期资源验收。Claude 本地能力继续完善；仅账户额度实地读取暂缓。

## 后续需要逐个收敛

- 通过真实资源基线核对已确认的 Swift + AppKit 方向；不重复询问已决定的菜单栏形态。
- 是否接受一次开启监控 hooks、一次 Codex hook 信任，以及按需的系统凭据访问授权。
- 许可证、是否需要首期支持 Intel Mac，以及签名公证与分发方式；用户已要求建立公开 GitHub 仓库。

这些问题不阻碍 Codex 首版本使用。当前没有安装 hooks、不更改 Agent 配置或 auth.json；已在内存读取 Codex 登录凭据并进行官方账户额度查询。用户已授权首次提交并发布到公开 GitHub 仓库；构建产物、本机凭据与过程文件不提交，开发报告中的实际账户用量已脱敏。
